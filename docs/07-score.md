# 07. 点数計算（符・翻）

> 対応フェーズ: フェーズ2 ｜ 関連要件: REQUIREMENTS.md §3.2（点数計算）, §8（フェーズ2）
> 依存: #06

## 目的
役・ドラ・和了形から符・翻を計算し、最終的な点数の授受を確定する。

## 対象ファイル
- `src/lib/mahjong/score.ts`（純粋TS）

## スコープ / 仕様
> **符の所在（#06で確定済み）**: 符は #06 `yaku.ts` の `computeFu` で算出し `YakuResult.fu` で渡される（点数最大化に「翻同点なら符が高い解釈」を選ぶ必要があるため、和了形分解と同じ #06 で持つ）。本チケットは `totalHan + fu` を入力として**翻→点数・授受・精算**に専念し、符計算を再実装しない（必要な符規則の検証は #06 のテスト済み）。

- 本格的なリーチ麻雀の計算式に準拠（符・翻）。
- 符計算: 副底20符・面子/雀頭/待ち/和了方法の符・ツモ符・門前ロン加符・七対子25符固定・ピンフツモ20符 等。
- 翻→点数（満貫〜数え役満の頭打ち、親/子、ツモ/ロンの分配）。
- リーチ棒（1000点供託 §3.2）・本場は無し（1局制 §3.2）。
- 出力は**結果データ**（点数・成立役名・符翻）を返すのみ。表示・読み上げはUI/音声側（#14, #17）。シニア向けに「結果のみ大きく表示」する前提で、計算過程は内部完結（§3.2）。

## 実装メモ
- `src/lib/mahjong/score.ts`。`score(input): ScoreResult` と `scoreFromYaku(yakuResult, {isDealer, riichiSticks})`。純粋・プレーンデータ。
- 基本点 `base = fu * 2^(2+han)`。上限: 13翻+=数え役満8000 / 11–12=三倍満6000 / 8–10=倍満4000 / 6–7=跳満3000 / 5=満貫2000 / 1–4は素点、**素点≥2000 のときだけ**満貫2000にキャップ（**切り上げ満貫なし**＝30符4翻=7700/11600・40符3翻は満貫ではない）。`limitName` はキャップ時のみ非null。
- 支払い: 各支払いを100点切り上げ。子ロン=base×4 / 親ロン=base×6 / 子ツモ=親base×2＋他子base×1 / 親ツモ=子3人base×2。`total` は丸めず合算（公式表の非対称を再現）。
- `Payment` は判別共用体（`ron`/`tsumo-dealer`/`tsumo-nondealer`）。`winnerGain = total + 1000*riichiSticks`（供託は勝者自身の棒を含む）。本場=0（1局制）。
- ガード: `han>=1`・`fu>=20`・`riichiSticks>=0`（整数）でなければ throw。`hasYaku` は #06/#08 の責務。
- `yaku.ts` の `YakuResult`（totalHan/fu/isTsumo）のみ依存。
- `score.test.ts` 32件で公式点数表を網羅（子/親×ツモ/ロン×各翻符・満貫〜数え役満・満貫境界・リーチ棒・ガード・`scoreFromYaku` 結合）。**注記**: Plan agent 提供の参照表に 3翻40符の base 誤り（1280を1920と記載）があったが、実装の式が正しく検出。子3翻40符=5200・親3翻40符=7700 に修正。
