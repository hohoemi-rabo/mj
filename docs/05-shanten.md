# 05. シャンテン数計算

> 対応フェーズ: フェーズ1 ｜ 関連要件: REQUIREMENTS.md §3.3, §5.3, §8（フェーズ1）
> 依存: #02, #04

## 目的
手牌のシャンテン数（アガリまでの距離）と待ち牌を計算する。お助けモード・CPU思考の中核。

## 対象ファイル
- `src/lib/mahjong/shanten.ts`（純粋TS）

## スコープ / 仕様
- 通常形・七対子・（必要なら国士は対象外 §3.2）のシャンテン数を計算し、最小値を返す。
- 副露を考慮（鳴き後の残り面子数で計算）。
- **待ち牌の列挙**（聴牌時に有効牌を返す）— お助けモードのハイライト（§3.3）で使用。
- 受け入れ枚数（有効牌の種類）の算出 — CPU中・強の手作り（#09 / §3.4）で使用。
- パフォーマンス: お助けモードで頻繁に呼ぶため十分高速に。純粋関数で副作用なし。

## 実装メモ
- `src/lib/mahjong/shanten.ts`。牌は長さ34の counts 配列（`tileToIndex`）に集計。アガリ=−1、聴牌=0。国士・役満は対象外（§3.2）。
- **通常形**: 雀頭をトップレベルで列挙し、本体DFS（`decompose`）は4面子スロット（面子＋塔子）だけを最適化＝「雀頭なし5ブロック」誤判定を回避。終端 `8 - 2*setsUsed - partials`、雀頭ぶん −1。`setsUsed` は `meldCount` で初期化（副露を完成面子として算入。暗槓も1面子）。**字牌は順子・塔子にならず、数牌のスーツ境界（m9→p1等）をまたがない**ガードを `i<27 && i%9<=…` で実装。
- **七対子**: `6 - 対子数 + max(0, 7 - 種類数)`（純関数）。鳴き除外は combiner（`shanten`）で `meldCount===0` のときだけ min に含める。
- **待ち/受け入れ**: 13枚相当（3n+1）前提で `tiles.length%3===1` を assert。`ukeire` は各種+1してシャンテンが下がる牌＋残枚数（`Σ(4-手中)`）、`waits` は聴牌時のアガリ牌（=0→−1の受け入れ）。
- **Hand ラッパ**: `handShanten`（13/14枚可）/ `handWaits`・`handUkeire`（`drawn!==null` で throw＝13枚形のみ）。`hand.concealedWithDrawn`・`completedMeldCount` を利用。
- 公開戻り値は `Tile`（`tileFromIndex`、index順＝ソート順）。`tiles.ts`・`hand.ts` を再利用（再定義なし）。
- パフォーマンス: ≤14枚のDFS＋ukeireは34回評価で実用上十分高速（お助けモードで頻繁呼び出し可）。将来の最適化余地としてスーツ別事前計算テーブルを `shanten.ts` 冒頭にメモ。
- `shanten.test.ts` 30件で網羅（各待ち形・雀頭なし回帰・スーツ/字牌境界・七対子の重複減点・副露・受け入れ・ガード・Handラッパ）。**注意**: 字牌（東南西北白發中）は順子を作らない＝シャンテン期待値の手計算時は要注意（実装時にこの取り違えを1件修正）。

## 完了条件
- 代表的な手牌でシャンテン数・待ち牌が正しく、テストが通る。お助けモードの応答に支障ない速度。
